## 2. CubeMX 精确参数表（含 1.6s / 2.5s 备选）

> 公式（估算）：\((Reload + 1) \times Prescaler / LSI\)  
> 当前工程 `RCC.LSI_VALUE=32000`，按 32kHz 估算。

### 2.1 推荐默认（量产稳健起步）

- **Activated**: `Enabled`
- **Prescaler**: `64`
- **Reload**: `799`
- **Window**: `4095`
- **预计超时**: 约 `1.60s`

说明：`Window=4095` 等效先关闭窗口限制（避免早期调试被窗口约束干扰）。

### 2.2 备选（更宽松，便于初期联调）

- **Activated**: `Enabled`
- **Prescaler**: `64`
- **Reload**: `1249`
- **Window**: `4095`
- **预计超时**: 约 `2.50s`

### 2.3 不建议的初始配置

- 不建议一开始启用 Window 模式（`Window < Reload`），先确保系统稳定再收紧。
- 不建议超时 < 1.0s（当前代码存在白天 STOP/夜间复杂路径，初期误复位概率高）。

## 3. 与当前代码结构对齐的喂狗点清单（仅方案，不改代码）

> 原则：**健康喂狗**。只在“一轮关键任务完整执行后”喂狗，避免无脑掩盖卡死。

### 3.1 建议喂狗点（应喂）

1. **夜间路径末尾喂一次**
   - 顺序：`DayNight_Update()` / `Charge_Update()` / `BattUndervolt_Update()` 已执行，且夜间分支内
   - 夜间关键任务：`Sync_MainLoop()` + `RF_Recovery_Check()` + `SyncLamp_Update()` 完成后喂
   - 目的：保证同步主流程、恢复流程都没卡住

2. **白天 STOP 唤醒恢复完成后喂一次**
   - 唤醒后完成：
     - `SystemClock_Config()`
     - `PeriphCommonClock_Config()`
     - `HAL_InitTick()`
     - `Day_RestoreFromStopWake()`
   - 然后喂狗
   - 目的：确保 STOP→RUN 恢复链路是健康的

3. **初始化末尾喂一次（可选）**
   - 在外设初始化、RF 初始配置完成后喂一次
   - 目的：作为系统进入稳态循环的起点

### 3.2 明确不喂狗场景（禁止喂）

1. **欠压准备进入 Standby 路径**
   - 检测到欠压并即将 `Undervolt_EnterStandby()` 时，不喂狗
   - 避免把应进入保护态的流程延后或掩盖

2. **错误死循环/故障停机路径**
   - 如 `Error_Handler()` 的 `while(1)`
   - 目的：让 IWDG 接管复位

3. **等待循环内部**
   - 不在任何“等待条件成立”的循环内喂狗
   - 目的：防止“卡住但仍被持续喂狗”

---

## 4. 启用顺序建议（防风险）

1. 先在 CubeMX 仅启用 IWDG，其他外设不改；
2. 先采用 `1.6s` 方案（`Prescaler=64`, `Reload=799`）；
3. 首轮只做最小喂狗点（夜间末尾 + 白天恢复后）；
4. 稳定后再考虑改成 `2.5s` 或引入窗口模式做更严格约束。

## 5. 验证口径（启用后执行）

- 观察复位原因统计（区分 IWDG/BOR/PIN）。
- 450ms 压测场景中确认：
  - 无异常频繁复位；
  - 出现异常阻塞时可自动恢复。
- 白天 STOP 与欠压 Standby 场景下无误复位风暴。
